# 技術調査 (ライブラリドキュメント)

ライブラリ・フレームワーク・SDK・API・CLI ツール・クラウドサービスの仕様や使い方を調べる場面で、学習データに頼らず現行ドキュメントで裏取りするためのルール。取得の具体手順 (Context7 CLI の実行方法・ライブラリ ID の選択基準・クエリの書き方・エラー処理) は `find-docs` skill に委譲し、この節は「いつ使うか」と「subagent へ委譲するときの扱い」を定める。

## 原則

- MUST: ライブラリ・フレームワーク・SDK・API・CLI ツール・クラウドサービスの API 構文・設定方法・バージョン移行・セットアップ手順・CLI の使用方法を調べるときは、`find-docs` skill を使う。ユーザの質問に回答する場面と、実装計画を立てるための調査の場面の両方に適用する。
- MUST: 答えを知っていると思っても、学習データだけで回答・計画しない。`find-docs` で取得できなかった場合は取得不可の事実を伝え、該当箇所の回答・計画を保留する (skill の「エラー処理」節に従う)。
- 適用境界は `find-docs` skill の description に従う。リファクタリング・ゼロからのスクリプト作成・ビジネスロジックのデバッグ・コードレビュー・一般的なプログラミング概念の調査には使わない。コードベース内のシンボル・参照の調査 (lsp ルール) や grep による探索も本ルールの対象外。
- 同一の論点 (ライブラリと質問の組) について一度取得した結果は、同じ会話内で再利用してよい。取得済みの結果で足りるのに再取得しない。

## subagent へ委譲するときの扱い

- `research-worker` subagent は `Skill` ツールを持たないため、`find-docs` を直接起動できない。ライブラリ仕様の調査を `research-worker` へ委譲する場合は、委譲プロンプトで `~/.claude/skills/find-docs/SKILL.md` を Read してその手順どおりに実行するよう明示し、取得したドキュメントの要点と Source URL を返させる。
- 委譲せず、メインループ自身が `find-docs` を起動してもよい。
- `implementer` へ渡す実装計画にライブラリ仕様が関わる場合、その仕様は委譲前にメインループが `find-docs` で確定して計画に書き下す (model-split ルールの「調査はメインループが行う」に従う)。implementer に取得させない。
